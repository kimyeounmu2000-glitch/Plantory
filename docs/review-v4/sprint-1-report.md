## 5. 회귀 및 데이터·보안 평가

확인한 범위에서 기존 저장·이전·백업·성장·하루 1회 꽃·40종 멘트·3D·정원에 회귀 실패 없음. 가짜 데이터만 사용했고 실제 기록 삭제·초기화·이전 없음. 날짜 YYYY-MM-DD, 시간 HH:mm, v2/v3 키와 저장 구조 유지.

입력 제목/메모의 무해한 HTML 공격 문자열이 텍스트로 표시되고 실행되지 않음. 손상 JSON, 지원하지 않는 version, 중복 ID, 잘못된 색상, 15,001개 항목, 4MB 초과 파일이 거절되고 기존 raw 저장 문자열 유지. 정상 JSON은 다른 확장자라도 구조를 검증해 복원되며 파일 확장자만 신뢰하지 않는다. 브라우저 프로세스를 종료하고 같은 격리 프로필로 재시작한 기록도 원문 동일.

추적 파일 40개의 제한된 고확신 비밀 값 패턴 검사에서 발견 0. Git 전체 이력·모든 비밀 형식의 부재를 보장하지 않는다. 원본 로컬 프로필과 connection 토큰은 보고/업로드 대상에서 제외한다. 번들 Three.js revision 170/MIT 확인. 공식 보안 페이지에 게시 권고가 보이지 않는다는 사실은 취약점이 없다는 보증이 아니며 임의 업데이트하지 않았다. 앱 계정 서버가 없어 서버 로그인 공격 검사는 해당 없음.

참고한 기준: [W3C 모달 포커스 지침](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/), [Three.js 보안 공지](https://github.com/mrdoob/three.js/security), [Three.js 버전 변경 안내](https://github.com/mrdoob/three.js/wiki/Migration-Guide). 접근성 일부 동작 검사이며 WCAG 전체 적합성 인증이 아니다.

## 6. 남은 문제·미실시

- **Alt+Tab 창:** 읽기 전용 프로세스 확인에서 Plantory 제목의 Chrome/Edge 창 0, bridge·테스트 프로필에 해당하는 프로세스 0. 이번 bridge shutdown 성공. 다른 프로세스 종료/프로필 삭제 없음. 이전 잔류 창은 재현되지 않아 원인 미확정. bridge는 timeout 시 context만 닫고 shutdown까지 서버/browser를 유지하는 구조여서 잔류 가능성을 검토했으나, 이것이 당시 보이는 창의 원인이라는 증거는 없다. 재발 시 창 제목·시각·해당 PID/부모 PID와 테스트 종료 로그를 연결해서 조사한다.
- 실제 iPhone Safari·Android Chrome, 화면 키보드·Safe Area·스크린리더·OS 강제 종료·실제 디스크 용량 고갈은 미실시. 모의 화면/예외 주입으로 대체 통과하지 않는다.
- 첫 자동 도움말은 열기 버튼 없이 시작하므로 닫은 직후 복귀할 버튼이 없고 제어 요소에 초점이 잡히지 않는 관찰이 있었다. 수동으로 연 모달의 원래 버튼 복귀는 통과했다. 첫 화면 초점 정책은 사용성 검토 대상으로 남긴다.
- 사이트 데이터 전체 삭제, 같은 origin의 악성 코드, 장치 분실, 구 앱의 v2 원본 자체 편집까지 현재 보호 로직이 막지는 못한다. 별도 백업 필요. 큰 정상 백업의 성능 스트레스·전체 Git 이력 보안 감사 미실시.
